# Step 2.2 Receipt — Silent Upgrade Detector

## What Changed

- Added manifest dependency history for `package.json`, `pyproject.toml`, and `requirements.txt` so scans can compare saved source declarations across runs.
- Added a silent-upgrade detector that uses existing SBOM component history to flag:
  - direct dependencies that appear or jump major versions while their manifest declaration is unchanged
  - transitive dependencies that appear or jump major versions while source manifests stay unchanged
- Added medium-severity `silent-upgrade` findings and calm case copy that says to verify or revert, not assume compromise.
- Annotated the Dependencies "Changed since last scan" cards with direct/transitive silent-upgrade labels and reasons.
- Rebuilt bundled dashboard assets from the React source.

## Acceptance Notes

- Detection uses saved SBOM component deltas; it does not parse lockfiles directly.
- Routine patch upgrades inside an unchanged manifest range are ignored.
- Direct and transitive silent changes are distinct in the dashboard payload and UI labels.
- First scans keep the existing "no previous scan" state.
- Matching manifest changes are treated as explained movement, not silent upgrades.
