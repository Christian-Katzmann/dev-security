# Step 1.2 — Add the `active_incident` action_level (closed enum in two places)

## What changed
Added `active_incident` as a first-class **top** action_level (ranked above `fix_now`)
for cases with a confirmed intrusion near their node. The action_level set is
validated in two places and an unknown value silently coerces to `verify`, so both
were extended; every ordering map now ranks `active_incident` at the top.

## Files touched
- `src/security_observatory/model.py` — `SecurityCase.__post_init__` validation set
  now `{"active_incident", "fix_now", "verify", "watch", "info"}`.
- `src/security_observatory/priority.py` — `ACTION_LEVELS` set extended;
  `_attention_rank` renumbered `{active_incident:0, fix_now:1, verify:2, watch:3, info:4}`
  (fallback updated 3→4). Renumber is monotonic, so all relative comparisons
  (the consequence-boost promotion at L112, the boost guard at L186) are unchanged.
- `src/security_observatory/cases.py` — `_ACTION_LEVEL_RANK` renumbered with
  `active_incident:0` at top (fallback 9 kept).
- `src/security_observatory/dashboard_pages.py` — both case-sort rank dicts (L449, L718)
  renumbered with `active_incident:0`. The label render at L458 uses
  `.replace("_", " ")`, so it renders "active incident" with no label-map change needed.
- `dashboard-ui/src/dashboardData.ts` —
  - `AttentionBucket` type gains `'active-incident'`.
  - `attentionBuckets` array prepends `'active-incident'` (this array's order drives the
    UI sort via `attentionBuckets.indexOf` in `sortDisplayCases`, so top position = sorts first).
  - `attentionBucketLabels` gains `'active-incident': 'Active incident'`.
  - `actionBucketCounts` initial record seeds `'active-incident': 0`.
  - `normalizeBucket` now translates the backend `active_incident` → kebab `active-incident`
    (alongside the existing `fix_now` → `fix-now`) and accepts it.
- Built dashboard assets regenerated under `src/security_observatory/dashboard/assets/`.

## Tests added
- `tests/test_model.py` — `active_incident` (and all known levels) survive `__post_init__`;
  unknown values still fall back to `verify`.
- `tests/test_cases.py` — a **low-severity** `active_incident` sorts above a **critical**
  `fix_now` via the real `apply_consequence_priority` sort path — proves action_level leads,
  not severity, and that the new state reaches the very top.
