# Step 1.1 — Bind a honey key to an asset node + suggest top-consequence placement

## What changed

1. **`asset_node_id` column on `honey_keys`** — the brand-new bridge linking a Honey
   Key to the asset node it guards.
   - `storage.py` SCHEMA `honey_keys` table: added `asset_node_id integer` (for fresh DBs).
   - `storage.py` `_ensure_columns`: additive, idempotent `alter table … add column
     asset_node_id integer`, mirroring the `note` column. **No `SCHEMA_USER_VERSION`
     bump** (that gate is destructive-rebuild only).
   - `storage.create_honey_key`: new optional `asset_node_id: int | None = None` param,
     written in the insert. `_public_honey_key` already returns all columns, so the
     bound id surfaces on read with no extra code.

2. **"Suggest placement" surface** — `consequence.suggest_placement_node(node_rows,
   edge_rows) -> PlacementSuggestion | None`.
   - Ranks every node by `_consequence_score` (reaches-crown-jewel > stronger path >
     nearer > larger blast radius) over `compute_node_consequences`.
   - **Crown-jewel present:** picks the highest-consequence surface that reaches it
     (`ranked_by = "crown_jewel_reachability"`).
   - **No crown jewel (the common case):** degrades honestly to raw `blast_radius`
     (`ranked_by = "blast_radius"`) and warns "label a crown jewel in
     `.devsec/crown-jewels.json` to sharpen this."
   - Presents the node by **human-readable `label`** (+ node_type), never by asking a
     human to author a 24-hex `component_fingerprint`. The fingerprint rides along as
     `identity_key` only for the machine binding.
   - `auto_plant_safe` honesty gate (`_placement_is_confident`): **False** for a
     weak/unknown node, for a crown-jewel path with any weak/unknown hop, and for a
     node with blast radius 0. A weak node is never pre-offered for auto-placement.
   - Copy says **"high-consequence dependency surface,"** never implies a guarded
     database (per Step 0.1: Campaign 1 proved dependency reachability only).

3. **Endpoint `GET /api/honey/suggest-placement?repoPath=&repoName=`** (read-only).
   - Resolves latest scan → `list_asset_nodes`/`list_asset_edges` → `suggest_placement_node`.
   - Returns the suggestion, a `recommended_placement_path` under `.devsec/honeykeys/`,
     and a **decoy_preview** (snippets minted in-memory, NOT stored — the real key is
     minted only on create). Honest empty states for "no scan" / "no graph nodes."
   - **Nothing is minted, bound, or written.** Proposal only.

4. **`POST /api/honey/keys`** now accepts optional `assetNodeId` (validated positive
   int via `_coerce_asset_node_id`; junk → HTTP 400) and binds it at mint time. This is
   the human-confirmed step. Planting (`/api/honey/insert`) is unchanged — all existing
   rails intact.
