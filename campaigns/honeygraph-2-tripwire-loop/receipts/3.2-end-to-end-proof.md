# Step 3.2 — End-to-end proof + honest verdict

## What this step did

Drove the whole tripwire loop **over real HTTP against a live dashboard server
bound to `127.0.0.1`** (not an in-process unit assertion), then wrote the honest
verdict that separates what the loop proves from what it doesn't.

## The end-to-end run (observed across the HTTP boundary)

A live `DashboardHandler` was booted on an ephemeral loopback port and the loop
walked over the wire:

1. `GET /api/graph` — baseline: 2 nodes, 1 edge, `active_incident=None`.
2. `POST /api/honey/keys` with `assetNodeId` → mint + bind a decoy to the
   top-consequence node (`placement_mode=local`, loopback callback notice).
3. `POST /api/honey/trigger` with the raw token → `{"accepted": true}`.
4. `GET /api/summary` → `case-web` (AT the node) flipped to `active_incident`
   with the real lit path; `case-other` (unrelated) stayed `verify`.
5. `GET /api/graph` → exactly one `active_incident` lit, on the tripped node,
   lighting its real blast path — nothing else.

Full transcript is embedded in `notes/3.2-loop-verdict.md`.
