# Step 2.1 — Crown-jewel labels + reachability scoring

## What landed

Human-labeled crown jewels + a pure, confidence-aware graph traversal that scores
each finding's case by **reachable consequence**, attached to every `SecurityCase`
and persisted with the scan. No interactive prompt anywhere (unattended-safe).

### New module: `src/security_observatory/crown_jewels.py`

- `CROWN_JEWELS_RELATIVE_PATH = ".devsec/crown-jewels.json"`.
- `load_crown_jewel_labels(repo_path)` — reads the committed file. **Never raises**:
  absent / empty / malformed file ⇒ `[]` (graceful, no crash, no prompt).
- `parse_crown_jewel_labels(data)` — pure; accepts `{"crown_jewels": [...]}` or a
  top-level list. Entries are a bare identity-key string or `{identity_key,
  node_type?}`; junk entries dropped, dupes deduped, unknown `node_type` downgraded
  to "match any type" (a typo never silently deletes a crown jewel).
- `mark_crown_jewels(nodes, labels)` — **pure**: returns new frozen `AssetNode`s
  with `is_crown_jewel` set where a label matches by `identity_key` (+ `node_type`
  when given). Never mutates inputs. Crown jewels are matched, **never inferred**.

### New module: `src/security_observatory/consequence.py`

- `Consequence` dataclass + `to_dict()`. Fields:
  `reaches_crown_jewel, distance, blast_radius, confidence, crown_jewels_defined,
  path, crown_jewel`.
- `compute_node_consequences(node_rows, edge_rows)` — pure. BFS/Dijkstra over the
  **blast-propagation graph** from every node. Accepts both input shapes
  transparently: in-memory `AssetNode`/`AssetEdge` (identity-keyed) **and** the
  storage-reader dicts (numeric `id` / `src_node_id` / `dst_node_id`) — so 3.1 can
  recompute from `list_asset_nodes` / `list_asset_edges`.
- `case_node_identities(case)` + `attach_consequences(cases, nodes, edges)` — maps
  each case to its node(s) by existing identity (component fingerprint, secret
  file path, coarse IaC file path) and sets `case.consequence` in place. A case
  that maps to **no** node is left untouched (`consequence` stays `None`).

### Edge orientation (the load-bearing correctness detail)

The blast graph follows "src compromised ⇒ dst at risk":
- `reachable_from` (secret→resource), `stored_in` (resource→datastore), `unlocks`
  are already oriented this way → followed **forward**.
- `depends_on` points consumer→provider, so blast flows provider→consumer →
  followed **backward**. (A vulnerable transitive package "reaches" the things
  that pull it in — verified by `test_depends_on_is_walked_backward`.)

### Weakest-link confidence

Consequence confidence = the **lowest** confidence on the chosen path (every edge
*and* node on it). One weak hop ⇒ weak consequence. Among equal-distance paths the
search prefers the strongest weakest-link (a readable tiebreak), so a strong path
is shown over a weaker same-length one.

### Honest "unknown" vs "zero"

- No crown jewels labeled at all ⇒ `crown_jewels_defined=false`,
  `reaches_crown_jewel=false`, `confidence="unknown"`, `distance=null` — "we can't
  assess", not "reaches nothing".
- Crown jewels defined but this node can't reach one ⇒ `crown_jewels_defined=true`,
  `reaches_crown_jewel=false` — a definite "reaches no crown jewel".
- Case not in the graph ⇒ `consequence = None` ⇒ ranks exactly as today.

### Wiring

- `model.SecurityCase` gains a `consequence: dict | None` field (sanitized in
  `__post_init__`, like `install_recency`). Serializes through `to_dict()` →
  `cases_json` + the normalized report, so it persists with the scan for free.
- `storage.save_scan(..., crown_jewels=...)` applies `mark_crown_jewels` to the
  nodes it derives before persisting, so `asset_nodes.is_crown_jewel` is set at
  scan time. (Single derivation seam preserved — marking is one extra pure pass.)
- `scan_orchestrator.scan_repo` loads labels, assembles the *same* nodes+marks and
  edges save_scan will persist, and calls `attach_consequences(cases, …)` before
  `save_scan`. Derivation is pure/deterministic, so the in-memory graph used for
  scoring matches the persisted graph exactly. The edge list assembled here is
  reused for the `replace_asset_edges` call (no double work).

### Committed crown-jewel file

`.devsec/crown-jewels.json` — committed, human-editable, ships with an **empty**
`crown_jewels: []` (this repo has no IaC datastore to label) plus `_comment` /
`_how_to_find_identity_keys` / `_examples` guidance the loader ignores.

## Open question — answered

**Blast-radius metric:** ship **both**, because each is a different, readable
signal and both are nearly free from the one traversal:
- `distance` = min hops to the nearest crown jewel ("how close to the crown jewel").
- `blast_radius` = count of nodes reachable via blast propagation ("how much this
  touches"), independent of crown jewels.
No opaque composite score — 2.2 ranks on `reaches_crown_jewel` → path confidence →
nearer distance → larger blast_radius, all of which a human can read directly.
