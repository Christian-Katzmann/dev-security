# Step 1.1 — Asset-graph schema + node derivation

## What landed

The asset-graph foundation: two new SQLite tables, a pure node-derivation module,
and the storage seam steps 1.2/1.3/2.1 build on. Edges are defined (table +
dataclass + persist API) but **no edges are derived yet** — that's 1.2/1.3.

### New module: `src/security_observatory/asset_graph.py`

- **Vocabularies (canonical source of truth):**
  - `NODE_TYPES = (secret, component, resource, datastore, endpoint)`
  - `EDGE_TYPES = (unlocks, depends_on, reachable_from, stored_in)`
  - `CONFIDENCE_LEVELS = (unknown, weak, strong)`
  - `DERIVED_NODE_TYPES = (component, secret, resource)` — what *this* step mints.
- **`AssetNode`** (frozen): `node_type, identity_key, label, confidence, is_crown_jewel=False`. Validates type/confidence in `__post_init__`.
- **`AssetEdge`** (frozen): `src_identity_key, dst_identity_key, edge_type, confidence, reason`. Addressed by node **identity_key**, not numeric id, so a derivation step emits edges without knowing the ids the DB assigns.
- **`derive_asset_nodes(*, components, findings, rotation_surfaces)`** — pure, side-effect-free. Dedups on `(node_type, identity_key)`; on collision keeps the stronger confidence. Returns a sorted list.
- `stronger_confidence(a, b)` helper.

### Node identity + confidence (the honesty rule)

`confidence` on a node = "how sure are we this is a real, identified asset":

| node_type | source | identity_key | confidence |
|-----------|--------|--------------|------------|
| component | `sbom_components` | `component_fingerprint` (from `sbom.py`) | strong |
| secret | gitleaks/trufflehog/trivy secret findings (category `secrets`) | the secret-bearing **file path** | strong |
| secret | rotation surfaces (`enumerate_rotation_surfaces` / `rotation_surfaces_json`) | the surface **path** | weak |
| resource | checkov findings (category `iac`) | the IaC **file path** (coarse) | weak |

Identity reuses DëvSec's existing identities so the graph lines up with how
`cases._cluster_key` already groups findings (secrets cluster by `file`,
components by fingerprint). Version change ⇒ different `component_fingerprint` ⇒
distinct node (verified by test).

### Schema: `src/security_observatory/storage.py`

- `asset_nodes` — `id, scan_id, repo_name, node_type, identity_key, label, is_crown_jewel (default 0), confidence, created_at`, FK → `scans(id)`. Unique index on `(scan_id, node_type, identity_key)` makes identity the physical contract.
- `asset_edges` — `id, scan_id, repo_name, src_node_id, dst_node_id, edge_type, confidence, reason, created_at`, FKs → `scans(id)` and `asset_nodes(id)`.
- CHECK enums (`node_type`, `edge_type`, `confidence`) are **generated** from the `asset_graph` vocabularies via `_sql_in_check` + `__…__` substitution — same drift-proof pattern as `CASE_DECISION_STATUS_CHECK`. Constants exported: `ASSET_NODE_TYPE_CHECK`, `ASSET_EDGE_TYPE_CHECK`, `ASSET_CONFIDENCE_CHECK`.

### Migration (no data loss)

Both tables are added with `create table if not exists` inside `SCHEMA`, which
`_connect_and_initialize` runs on **every** open. So an existing history DB gains
both tables on next launch with **no destructive rebuild and no `user_version`
bump** — they're purely additive, like the `_ensure_columns` column adds. (Test:
a legacy DB with only `scans` gains the tables, existing rows intact.)

### Persistence + the seam for 1.2/1.3/2.1

- `save_scan` now derives nodes via `derive_asset_nodes(components, findings)` and
  inserts them (replace-by-scan, edges-before-nodes for the FK). No signature
  change, no orchestration change — it derives from artifacts it already holds.
- `list_asset_nodes(scan_id, repo_name)` / `list_asset_edges(...)` readers.
- **`replace_asset_edges(scan_id, repo_name, edges)`** — the edge seam. Takes
  `AssetEdge`s addressed by identity_key, resolves each endpoint to the node id
  already stored for that scan, **skips edges whose endpoints don't exist** (so it
  never mints duplicate nodes), returns the count written. This is what 1.2/1.3
  call.

## Open questions — answered

- **Minimal node_type set Phase 2 traverses:** `secret → resource/datastore` (the blast-radius path) and `component → component` (dependency reachability). 1.1 derives `component`, `secret`, `resource`. `datastore` is a valid type but **reserved for 1.3** (needs resource-type classification from the IaC graph). `endpoint` is in the enum but **nothing produces it** — see below.
- **Endpoints in MVP?** **Deferred.** No artifact DëvSec collects cheaply yields endpoints, so 1.1 mints none. `endpoint` stays valid in the schema enum (zero cost, avoids a future migration) but is unused until something produces them. Surfaced, not assumed.

## Notes for the next steps

- **1.2:** emit `AssetEdge(..., edge_type='depends_on')` keyed by `component_fingerprint`; persist with `replace_asset_edges`. Don't mint nodes.
- **1.3:** the resource nodes 1.1 mints are **coarse (file-level, weak)**. To get real per-resource + `datastore` nodes, **extend `derive_asset_nodes`** (keep derivation in that one function) rather than inserting nodes from a new path. `replace_asset_edges` resolves by identity_key alone — give resource vs datastore distinct identity_keys.
- **2.1:** crown jewels match on node `identity_key`; set `asset_nodes.is_crown_jewel = 1` at scan time. Read the graph with `list_asset_nodes`/`list_asset_edges`; both carry `confidence` for the weakest-link rule.
