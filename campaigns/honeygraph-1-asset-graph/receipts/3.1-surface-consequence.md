# Step 3.1 Receipt — Show "why this ranks here" in the dashboard

## What changed

### `dashboard-ui/src/dashboardData.ts`
- Added `ConsequencePathStep` type (matches backend `_node_summary` dict shape: `identity_key`, `node_type`, `label`, optional `via`)
- Added `ConsequenceSummary` type (matches `Consequence.to_dict()` output: `reaches_crown_jewel`, `distance`, `blast_radius`, `confidence`, `crown_jewels_defined`, `path`, `crown_jewel`)
- Added `consequence?: ConsequenceSummary | null` field to `SecurityCase` (wire shape)
- Added `consequence?: ConsequenceSummary | null` field to `DisplayCase` (UI shape)
- Wired `item.consequence as ConsequenceSummary | null | undefined` through `caseToDisplayCase`

### `dashboard-ui/src/App.tsx`
- Imported `ConsequenceSummary`, `ConsequencePathStep` from `dashboardData`
- Added `formatConsequencePath(path)` helper: renders path as `label → via → label → via → label`
- Added `ConsequenceLine` component: shows compact "path (N hops, confidence)" line; returns null when `reaches_crown_jewel` is false (no empty scaffolding); shows caveat for weak/unknown confidence
- Integrated into `CaseDetailCard` right after `<p>{item.why}</p>`, guarded by `item.consequence?.reaches_crown_jewel`

### `dashboard-ui/src/index.css`
- Added `.consequence-line` (amber-tinted block, border, radius)
- Added `.consequence-path` (monospace, warn-ink color)
- Added `.consequence-caveat` (italic, muted, block below path)

## Acceptance criteria met
- UI uses real payload consequence data — no placeholders, consequence flows from `cases_json` through `caseToDisplayCase` to `DisplayCase`
- A case with no consequence (or `reaches_crown_jewel=false`) shows nothing new — the render guard is `item.consequence?.reaches_crown_jewel`
- Confidence is visible in the path label; weak/unknown path shows an explicit caveat
- `npm run lint` and `npm run build` both pass clean
