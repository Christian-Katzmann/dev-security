# Receipt: Step 3.1 - Add optional trust enrichment

Date: 2026-05-12

## Summary

Added the first dependency trust layer without changing default local scan behavior:

- Added `--trust` as an explicit opt-in path for network-backed dependency trust enrichment.
- Added `--trust-cache-only` for offline reuse of already cached trust data.
- Added cache-backed dependency trust records for:
  - source repo
  - source-repo resolution confidence and reason
  - OpenSSF Scorecard score and status
  - OpenSSF Criticality score and status
  - checked-at timestamp
  - freshness
  - overall status
- Added conservative source-repo resolution for direct GitHub package URLs, Go GitHub module paths, and explicit GitHub repository metadata.
- Unknown source repositories now produce `unknown_source` trust records instead of being treated as weak hygiene.
- Stale and unavailable cache states are preserved in the record instead of being hidden.

## Behavior Notes

- Default scans still do not call Scorecard, Criticality, GitHub, or external APIs.
- `security-scan --trust` runs Syft and then refreshes OpenSSF trust data for components with a confidently resolved GitHub source repo.
- `security-scan --trust-cache-only` runs the same enrichment path without network access.
- Cache files are scoped under `~/.security-observatory/cache/dependency-trust/scorecard/` and `~/.security-observatory/cache/dependency-trust/criticality/`.
- Scorecard cache freshness uses a 7-day TTL. Criticality cache freshness uses a 30-day TTL.
- Unknown npm/PyPI-style package names are not guessed into GitHub repos.
- Trust facts are stored separately from findings so Step 3.2 can decide how to use them in prioritization and UI without rewriting scan history.
