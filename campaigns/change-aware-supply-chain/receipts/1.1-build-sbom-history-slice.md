# Receipt: Step 1.1 - Build the SBOM history slice

Date: 2026-05-12

## Summary

Implemented the first SBOM history foundation slice:

- Added a normalized `SBOMComponent` model and parser helpers for CycloneDX and Syft JSON.
- Added SQLite persistence for one component row per scan component record.
- Wired scan-time persistence so Syft SBOM output is parsed and saved with the scan.
- Kept missing optional metadata as `NULL` fields instead of treating it as a failure.
- Added fixture tests for parser fields, missing metadata, stable fingerprints, schema creation, scan-time persistence, missing Syft, and partial SBOM output after a Syft error.

## Behavior Notes

- Components are tied to both `scan_id` and `repo_name`.
- Component fingerprints are based on package identity, not scan location, so the same package/version remains stable across scans while version changes produce a new fingerprint.
- The parser prefers `sbom.cyclonedx.json` and falls back to `syft.json`.
- A missing Syft scanner still records a partial scan without components.
- A Syft error that leaves partial SBOM metadata records a partial scan and saves whatever component fields are available.
- Existing finding, case, dashboard payload, and scan export behavior remains compatible.
