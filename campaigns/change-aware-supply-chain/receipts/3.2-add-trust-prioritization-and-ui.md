# 3.2 Add Trust Prioritization and UI

## What changed

- Dependency trust facts now work from both saved trust dictionaries and in-memory trust record objects.
- Low-hygiene, high-importance dependencies can raise attention to `verify`, but they do not silently jump a case to `fix_now`.
- Every trust boost carries a readable reason: weak maintenance signals, wide ecosystem use, and stale or missing data are explained separately.
- Missing project hygiene or ecosystem importance is treated as missing context, not as a penalty against the repo.
- Security case and dashboard types include `priority_reasons` so trust-driven attention stays traceable.
- The Dependencies view now separates five compact signals:
  - vulnerability/CVE risk
  - project hygiene
  - ecosystem importance
  - freshness
  - data state for stale, unknown, unavailable, or partial trust data
