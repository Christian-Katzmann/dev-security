# Receipt: Step 2.1 - Correlate findings with component changes

Date: 2026-05-12

## Summary

Implemented change-aware dependency vulnerability correlation:

- Trivy, OSV, and Grype dependency findings now preserve package name, installed version, ecosystem, package URL, fixed version, and vulnerability ID when scanners provide them.
- Dependency findings are matched to normalized package-list components by exact package URL first, then by package name, ecosystem, and version when reliable.
- Match confidence is explicit:
  - `strong` for exact package URL or confirmed name/ecosystem/version matches.
  - `weak` for likely but incomplete matches.
  - `missing` when no package-list entry can explain the finding.
- Saved findings now expose component match confidence, reason, component fingerprint, and package-change key.
- Dependency case evidence now includes the package/component match details.
- Dashboard case comparison now classifies dependency risk movement as:
  - `vulnerability-introduced`
  - `vulnerability-fixed`
  - `recurring-risk`
  - `unknown`
- Resolved dependency cases can explain when a package version change or removal appears to have fixed the issue.
- New dependency cases can explain when a package version change or addition appears to have introduced the issue.

## Behavior Notes

- Strong matches are explainable and stored with each finding.
- Weak matches use cautious wording and do not claim proof.
- Package upgrades can now be shown as security-positive, security-negative, recurring, or unknown depending on how findings move between scans.
- Dependency case language avoids SBOM/VEX/CVSS vocabulary and describes the user-facing meaning of the package change.
- Existing dependency grouping by vulnerability plus package remains stable.
