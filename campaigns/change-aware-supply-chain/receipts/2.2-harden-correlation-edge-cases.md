# Receipt: Step 2.2 - Harden correlation edge cases

Date: 2026-05-12

## Summary

Hardened change-aware dependency correlation for incomplete and ambiguous evidence:

- Ambiguous dependency-to-SBOM matches now return `uncertain` instead of weakly implying a likely match.
- Dependency change records now carry API labels for:
  - `Unknown`
  - `Weak match`
  - `Not checked`
  - `No CVE found`
  - `Known CVE`
- Dependency changes with no matching vulnerability findings remain visible as supply-chain changes.
- Clean dependency changes are labeled `No CVE found` only when a dependency vulnerability scanner completed.
- Changes are labeled `Not checked` when no CVE scanner completed.
- Missing package metadata is surfaced with warnings such as `Missing version`, `Missing purl`, and `Unknown ecosystem`.
- No-SBOM scans now include an explanation that package changes could not be compared because no package inventory was saved.
- The dashboard now shows CVE-check and match-confidence labels on dependency change cards.
- The dependency dashboard changed the ambiguous “Vuln reachable” label to “Known CVEs” to avoid false confidence.

## Behavior Notes

- Package rename or ecosystem ambiguity is now explicit: Observatory says the match is uncertain rather than pretending it knows the exact package.
- A dependency version or license change without CVEs is treated as a real supply-chain change, not as an empty state or scanner failure.
- “No CVE found” means a dependency vulnerability scanner completed and did not report a matching CVE for that changed package.
- “Not checked” means the dependency inventory changed, but Observatory did not get a completed CVE scanner result for that scan.
- “Unknown” is reserved for package metadata too incomplete to compare confidently.
