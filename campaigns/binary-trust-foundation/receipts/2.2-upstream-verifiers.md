# Receipt — Step 2.2: Wire real cosign verification at install

**Outcome:** Syft and Grype downloads are verified with real upstream cosign signatures at install; Gitleaks and Trivy stay at the honest checksum-pinned level.

## Per-tool verdict (from upstream-signing research)

| Tool | Upstream proof published | DëvSec proof level | Why |
|---|---|---|---|
| **Syft** | keyless cosign over `checksums.txt` (`.sig` + `.pem`), identity `anchore/syft/.github/workflows/release.yaml@refs/heads/main` | `upstream-signed` | Detached cosign verified, tarball matched against verified checksums. |
| **Grype** | same scheme as Syft (`anchore/grype/...@refs/heads/main`) | `upstream-signed` | Same path. |
| **Trivy** | cosign **Sigstore bundle** (`verify-blob-attestation --bundle`), identity pinned to the release **tag** | `checksum-pinned` | Bundle/attestation path differs from detached cosign and was not validatable offline. Documented fast-follow rather than ship an unverified verify invocation. |
| **Gitleaks** | none — only an **unsigned** `checksums.txt` | `checksum-pinned` | No signature to verify. DëvSec's source-pinned archive sha256 is a stronger root of trust than the upstream unsigned checksums file. |

Note the load-bearing detail: Anchore signs from the `@refs/heads/main` workflow ref, Trivy from the tag ref. Using the wrong ref suffix makes verification always fail, so the identities are pinned exactly per tool.

## Acceptance criteria

- [x] At least one managed scanner verifies via cosign instead of checksum-only — Syft **and** Grype.
- [x] Verification pins publisher identity + OIDC issuer where the format exposes them.
- [x] Unsupported tools remain installable only under their honest weaker proof level — Gitleaks/Trivy at `checksum-pinned`.
- [x] Verifier absence is reported as a setup gap, not hidden as success — `test_install_falls_back_to_checksum_when_cosign_absent`.
- [x] Tests do not require network or a real cosign binary — runner/fetch/which mocked (`test_install_verifies_cosign_signed_syft`).

## Fast-follow

Trivy's `cosign verify-blob-attestation --bundle <asset>.sigstore.json` path (tag-pinned identity `https://github.com/aquasecurity/trivy/.github/workflows/reusable-release.yaml@refs/tags/v<version>`) should be wired and validated against a real release to lift Trivy to `upstream-signed`. The `CosignProvider` is structured to take a second style without disturbing the detached path.
