# Receipt — Step 2.3: Surface proof levels in CLI and dashboard

**Outcome:** Proof levels are visible in CLI `doctor`, scanner status payloads, and the catalog/install preview — without implying that a signed scanner is safe or sandboxed.

## Changes

- [verification.py](../../../src/security_observatory/verification.py): `proof_level_label()` and `PROOF_SAFETY_CAVEAT` (one honest line: proof is origin, not safety).
- [model.py](../../../src/security_observatory/model.py): `ScannerStatus.proof_level` — flows into every scan's serialized scanner statuses.
- [scanners.py](../../../src/security_observatory/scanners.py): `run_scanner` sets proof level — managed→recorded level (floor `checksum-pinned`), tampered→`unverified`, PATH→`user-owned`.
- [managed_tools.py](../../../src/security_observatory/managed_tools.py): `ManagedToolEvidence.proof_level` (+ in `to_dict`); `build_tool_install_preview` adds `proof_level`/`proof_level_label` (installed), `expected_proof_level` (installable), and `proof_caveat`; detected tools surface `user-owned`.
- [cli.py](../../../src/security_observatory/cli.py): `doctor` prints a "DëvSec-managed tools (proof of origin, not safety)" section with proof level, verified state, and integrity-baseline presence.
- [dashboard-ui](../../../dashboard-ui/src/components/catalog/CatalogToolPage.tsx): "Binary proof" row in Setup and ownership + the safety caveat line; types extended in `dashboardData.ts`.

## Acceptance criteria

- [x] UI and CLI distinguish user-owned, checksum-pinned, upstream-signed, provenance-verified, and unverified where data exists.
- [x] Wording avoids implying a signed scanner is harmless or sandboxed — `PROOF_SAFETY_CAVEAT` shown in CLI section header and dashboard; doc reinforces it.
- [x] Missing proof appears as an evidence gap, not a scan failure — legacy installs show "no integrity baseline"; tampered (policy block) is the only refusal.
- [x] Python tests pass; dashboard `tsc` lint clean; `make dashboard-build` rebuilt bundled assets.
