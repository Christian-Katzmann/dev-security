# Receipt — Step 2.1: Verification provider contract

**Outcome:** Added [src/security_observatory/verification.py](../../../src/security_observatory/verification.py) and [tests/test_verification.py](../../../tests/test_verification.py) (14 tests).

## Acceptance criteria

- [x] Records can store proof level, verifier name, verified subject digest, source identity, and human-readable evidence — `VerificationResult` with `to_dict`/`from_dict` round-trip.
- [x] Supports checksum-only fallback without pretending it is signed — `ChecksumProvider` → `checksum-pinned`; `verify_managed_download` falls back to it.
- [x] External command verifiers may be unavailable and that state is reported cleanly — cosign absence → `available=False`, proof `unverified`, evidence note; orchestrator downgrades to checksum-pinned and carries the note.
- [x] No installer behavior change in this step — module is standalone; wiring lands in 1.2/2.2.

## Design notes

- Injectable `runner` (CommandRunner), `fetch` (Fetcher), and `which` make the whole contract testable with no network or real cosign.
- Failure semantics are explicit: a verifier that is *absent* downgrades (setup gap); a verifier that *ran and rejected* raises `VerificationError` (fail closed, possible tampering).
- `proof_rank` / `is_executable_proof` encode the policy from `docs/binary-trust.md` (`checksum-pinned`+ may execute).
