# Batch: 20-release-honesty

## Purpose
DëvSec's tree has moved 104 commits past its last tag, but every place a user or release manager would look to learn what shipped is frozen at `0.1.0`: `pyproject.toml` still reads `0.1.0`, the `CHANGELOG.md` has a single `[0.1.0]` entry with no `[Unreleased]` section, and the README "real vs not yet" table predates the work this campaign lands. That means real trust-posture changes — the guarded MCP case-resolution write-back, the guarded scan-trigger, the clean-room reviewer, the red-team e2e — are unrecorded, and a clean next release cannot be cut honestly. This batch owns the two release-honesty super-list items **S-046** (reconcile the changelog/version/tag triple, add and populate `[Unreleased]`) and **S-053** (keep the "real vs not yet" honesty true *after* this campaign's polish/feature work has landed). Their shared fix surface is the release-truth metadata — `CHANGELOG.md`, `pyproject.toml`/git tag, and the README "What's real vs. what's not yet" table — not product code.
