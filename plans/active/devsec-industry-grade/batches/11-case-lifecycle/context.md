# Batch: 11-case-lifecycle

## Purpose
The Brief's signature feel is watching a case move "open → in-progress → verifying → closed, with the diff and the verification that closed it" — and today that loop only half-closes. There is no canonical state machine for cases, two divergent four-value status enums describe the same case across the MCP and storage surfaces (**S-020**), and the visible lifecycle is flat: a case has no "verifying / awaiting rescan" beat, and closure is shown by *absence* (the case drops out of attention) rather than by proof bound to the scan + diff that closed it (**S-035**). Both items are the same missing seam viewed from two angles — the structural module and its UI/feature surface — so they share one fix surface: a new `lifecycle.py` state machine consumed by `cases`/`decisions`/`storage`/MCP/dashboard. Fixing them turns the product's headline promise from implicit into demonstrable.
