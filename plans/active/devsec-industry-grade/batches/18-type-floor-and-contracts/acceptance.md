# Acceptance: 18-type-floor-and-contracts

## Acceptance Criteria
- **S-021 (strict enabled):** `dashboard-ui/tsconfig.json` `compilerOptions` enables `strict` (or at minimum both `strictNullChecks` and `noImplicitAny`). `grep -E '"strict"|"strictNullChecks"|"noImplicitAny"' dashboard-ui/tsconfig.json` shows the flag(s) set to `true`.
- **S-021 (typecheck green under strict):** `cd dashboard-ui && npm run lint` (which is `tsc --noEmit`) exits 0 with strict on — every surfaced null/implicit-any error is fixed at the root with real `??`/guards, not silenced. `grep -rn "@ts-ignore\|@ts-expect-error\|as any\| any\b" dashboard-ui/src` introduces no new `any`/`@ts-ignore`/cast escapes versus the pre-batch baseline (the zero-`any` discipline is preserved, now enforced). `cd dashboard-ui && npm run build` (`vite build`) succeeds.
- **S-022 (frontend type trimmed to wire shape):** The `SecurityCase` type in `dashboard-ui/src/dashboardData.ts` no longer declares the dead aliases the backend never emits — `grep -n "plain_title\|why_matters\|action_bucket\|affected_path\|\bbucket\b" dashboard-ui/src/dashboardData.ts` shows those removed from the `SecurityCase` type definition (they may remain only inside `DisplayCase` normalization fallbacks if still consumed). The type matches the backend wire fields (`model.py:141-178`/`cases.py:378-395`) plus the documented server-injected fields (`inferred_secret_name`, `scan_id`, `repo`/`repo_name`, `change_status`, `decision`, `suppressed`, `suppression`, honey/incident fields). `caseToDisplayCase` still compiles and produces the same `DisplayCase` shape, and `cd dashboard-ui && npm run lint` stays green under the now-strict config.
- **S-022 (`save_scan` cannot bypass validation):** `save_scan` in `src/security_observatory/storage.py` no longer silently persists an un-redacted raw dict. Either its `cases` parameter is narrowed to `list[SecurityCase]`, or every dict input is routed through `SecurityCase(**case)` before persistence so `SecurityCase.__post_init__` redaction and the `action_level`/`confidence` whitelist always apply. A test demonstrates that a case containing a token-like string is redacted in the persisted `cases_json` regardless of whether it was passed typed or (if still accepted) as a dict. `uv run pytest tests/test_cases.py` passes (any dict-passing tests updated to typed cases).
- **S-022 (trust paths preserved):** The single-validator invariant and severity gate are untouched — `validate_case_resolutions` (`case_followup.py`) and the `set_case_decision` gate (`human_authorized` defaults `False`, high/critical suppression raises `HumanConfirmationRequired`) behave identically. `uv run pytest tests/test_severity_gate.py tests/test_red_team_e2e.py` passes (the "Unsafe AI write" non-negotiable stays demonstrably eliminated).
- **S-026 (versioned migrations):** Schema migrations are tracked by `PRAGMA user_version` — `grep -n "user_version" src/security_observatory/storage.py` shows the pragma being read and written. The destructive table rebuild (`_migrate_resolution_status_constraints`) is gated on a version bump rather than the `select sql from sqlite_master` substring sentinel, and the migration order is documented in code. A migration round-trip test opens an old-shape fixture DB (pre-`user_version` / narrow schema), runs `ObservatoryDB` init, and asserts the DB reaches the current `user_version` with data intact and is idempotent on a second open (no re-rebuild). `uv run pytest` (storage tests, including the new round-trip test) passes.
