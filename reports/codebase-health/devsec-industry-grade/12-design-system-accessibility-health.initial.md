# Design System & Accessibility Health — DëvSec (Security Observatory)

## Executive Finding

The Mistglass design system is mature and the accessibility layer is real but uneven — the headline is "consistent, broadly accessible, with concrete gaps that block keyboard and screen-reader users on specific flows," not a systemic failure. The visual system is strong: one `:root` token set (69 tokens, 839 `var(--…)` uses across the 7316-line stylesheet), a single `.button` primitive with consistent variants, a shared `.icon-button`, an explicit `.sr-only` utility, ~18 responsive breakpoints, honored `prefers-reduced-motion`, and crafted loading/empty/error/disabled states. Both safe checks pass clean: `tsc --noEmit` (exit 0) and `vite build` (exit 0, 1689 modules). Accessibility is *present* — 37 ARIA/role attributes across 11 component files (25 `aria-label`, 7 `aria-hidden`, 4 `aria-modal`, 1 `aria-expanded`; 4 `role="dialog"`, plus `role="button"`/`presentation`/`note`), an explicit `.sr-only` utility (defined + used), landmark elements (`<main>`, `<nav>`, `<header>`, `<aside>`, `<footer>`), and the one non-semantic clickable (the honey-card `<div>`) is correctly retrofitted with `role="button"`, `tabIndex={0}`, and an Enter/Space `onKeyDown`. The real gaps cluster around **keyboard focus**: there is **no global visible focus indicator** — the only two explicit `:focus-visible` rules (`.setup-card-input`, `.setup-card-textarea`, L5952/5978) set `outline: none` and replace it with a near-invisible `box-shadow: 0 0 0 1px var(--ink-strong)`, while every other interactive control (buttons, nav rows, links, the rest of the inputs) has *no* focus-visible style at all and relies on the browser default outline that the `.button`/`nav-row` base styles don't reinstate. The one `0 0 0 3px rgba(79,138,114,…)` ring in the file is decorative — it's on `.status-dot.live` at opacity 0.16 (L385), not a focus state. Second, the four `role="dialog"` modals declare dialog semantics but have **no Escape handler and no focus trap** (`Escape`=0, `.focus()`=0 in modal code) — a keyboard user can tab behind an open rotation/AI-write dialog and cannot dismiss it with the keyboard. There is also no skip link; severity is partly signaled by color-only elements (`.severity-rail`, posture-gauge tone); and there is no a11y test (or any test framework) in `dashboard-ui`, so DESIGN.md §11's "Accessibility floor" promises aren't guarded against regression. Design-system surface: **Green/Yellow**. Accessibility surface: **Yellow/Red** (real markup, but keyboard users lack a visible focus indicator and can't escape modals). Worst health is **Yellow/Red**, driven jointly by the missing global focus indicator and the modal focus-trap/Escape gap.

## Top Repair Targets

1. **Build one shared `Dialog` primitive and migrate all 4 modals (Rank 1, Yellow/Red).** Add focus trap, `Escape`-to-close, and focus restore on close to a single component, then replace the four ad-hoc overlays. Fixes a duplicated keyboard gap once and de-risks the rotation/AI-write flows where the gap matters most.
2. **Add a global visible focus indicator (Rank 2).** Define one `:focus-visible` rule on buttons/links/inputs/selects/textareas/clickable cards using a Mistglass token-based outline or box-shadow ring, and replace the two `outline: none` `:focus-visible` rules (`.setup-card-input`, `.setup-card-textarea`) with that visible ring. Today there is effectively no focus indicator across the dashboard's primary controls; this is the broadest, lowest-risk accessibility win.
3. **Add a minimal a11y test harness + a skip link, then reconcile DESIGN.md §11 (Ranks 3, 4, 6).** Wire vitest + jest-axe smoke over button names / dialog semantics / focus-visible so the floor can't silently regress; add an `.sr-only` "Skip to content" link to the existing `<main>`; and update §11 to either claim or defer the dialog-focus and `aria-live` items so the spec matches built behavior.

## Limits

- **No live render, no axe/Lighthouse, no contrast measurement.** AGENTS.md and `.adx/risks.json` forbid starting the dashboard server in this pass, so all findings are from static source, token values, and `DESIGN.md`. Contrast (Rank 5 and the DESIGN.md §11 contrast promise) was **not** verified against rendered pixels; the ink-on-paper palette looks AA-plausible, but mid-tone values (e.g. `--ink-faint #8d938f` on `--paper`, `--sev-warn #c98a3f`) should be confirmed with a real contrast tool before being called Green. Treat the contrast question as **Grey/unverified**.
- **The modal focus-trap/Escape gap is inferred from keyword absence**, not a live keyboard test. `role="dialog"`/`aria-modal` are confirmed present and `Escape`/`.focus()` confirmed absent in the modal components' source; the *consequence* (tab-behind, no keyboard dismiss) is a high-confidence inference from that absence, but the actual keyboard behavior was not driven in a browser.
- **An earlier evidence pass was corrupted by the repo's unicode (`ë`) path breaking some shell tooling**, which produced stale, contradictory counts. Those were discarded; this report's numbers come from a clean ASCII-path working copy of `dashboard-ui/src` plus direct Reads and a `tsc`/`vite build` run against the real repo. Verified facts that stand: 37 ARIA/role attrs across 11 files; 4 `role="dialog"` + `aria-modal` with **no** Escape/focus-trap; landmarks present; `.sr-only` present; and **no global focus ring** (the lone `0 0 0 3px rgba(79,138,114,0.16)` shadow is decorative on `.status-dot.live` at L385, and the only `:focus-visible` rules set `outline:none`). No repository file was modified except this report.
- **Counts are static-analysis over source**; a few may be off by small amounts (e.g. multi-line buttons, JSX spreads). The *direction* — accessibility is present-but-uneven, with the modal keyboard gap as the sharp edge — is robust across the ARIA census, the focus-selector scan, and the modal-keyword scan.
- **Behavioral/triage findings deferred.** Keyboard *flow quality*, alarm-fatigue, and progressive disclosure of the triage loop belong to `behavioral-ux-health-forensic`; this report covers only gaps rooted in the design-system primitives and the accessibility layer, per the no-sibling-overlap guardrail.
