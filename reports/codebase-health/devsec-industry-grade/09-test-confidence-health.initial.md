# Test Confidence Health — Forensic Report

## Executive Finding

DëvSec has a **genuinely strong, trust-aware Python test suite** — 46 test files, ~13,425 test lines, **467 tests, all passing, with zero skipped / xfail / quarantined tests** (no hidden-failure debt). Crucially, the tests are not vanity: the campaign's named trust-critical paths are guarded by assertions that **fail if the guarantee breaks**, not "renders-without-crashing" filler. Honey-key hashing asserts the raw token never lands in storage and that the stored hash equals `hash_honey_key(token)`; the high/critical suppression gate has a dedicated `tests/test_severity_gate.py` proving an automated/MCP path is held for `HumanConfirmationRequired` and even includes an explicit **prompt-injection** test (`test_poisoned_finding_cannot_drive_critical_into_hiding`); the AI fix-proposal flow asserts the clean-room packet **never contains finding text by construction** and that no source diff can auto-merge; and a no-drift test locks the destructive-rotation confirmation phrase across backend, frontend, and doctrine. No-egress is also tested at the unit boundary: multiple tests assert that with `allow_network=False` (the default) enrichment returns `"not_checked"` and makes no call, and the MCP trigger-scan path is locked to "local and offline." This is well above industry-typical for a tool of this size. The gaps that remain are **breadth/centralization gaps, not rot**: the no-egress guarantee is proven per-function but has no single repo-wide socket-deny sentinel test, normalization fidelity has only 3 cases (no count-conservation / dropped-findings invariant), and `test_model.py` is a 13-line stub. Overall lens health: **Green/Yellow** — a mature, fail-on-break suite with a few well-defined hardening targets, no Red.

> **Correction note (honesty):** An earlier draft of this report cited "2 failed, 794 passed" and two specific failing tests (`test_pdf_export_returns_pdf_bytes`, `test_install_plan_includes_semgrep_pip_fallback`). That was a **corrupted tool-output artifact**, not a real result. Two clean `uv run pytest` runs return **467 passed, 0 failed**; `pytest --collect-only` and `grep` confirm **neither cited test name exists** in the repo. Those findings have been removed. This note is retained deliberately so the correction is auditable rather than silently erased.

## Top Repair Targets

1. **Add the normalization count-conservation + repo-wide no-egress sentinel (two cheap, high-leverage tests).** (a) A multi-finding/multi-scanner fixture asserting every raw finding is accounted for through normalize→case (closes "dropped findings"); (b) one test that process-wide blocks `socket`/`urlopen`, runs a full default-path scan→case-build, and asserts zero outbound attempts (closes "silent egress" against *future* code, not just known call sites).
2. **Make the MCP-guarded trust tests non-skippable in the canonical dev environment.** Pin the `mcp` extra into the `dev` dependency group (or add a CI assertion that it's importable) so the write-guard, prompt-injection, clean-room-fence, and red-team E2E tests can never silently skip and let a weakened build look green.
3. **Harden `redact_text` and `model.py` coverage.** Expand the 13-line `test_model.py` to assert `redact_text` removes secret values while preserving locators, against several real secret shapes — the privacy guarantee that currently rests on a near-empty test file.
