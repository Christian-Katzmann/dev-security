# Documentation Health Forensic — DëvSec (Security Observatory)

## Executive Finding

DëvSec is documentation-rich and, where I could cross-check it against code, **documentation-honest** — closer to the Brief's "zero drift" bar than most repos this size. All five Brief-named surfaces exist (README, PROVOCATION.md, AGENTS.md, mcp/README.md, design/diagrams/trust-boundary.md), plus a full agent-contract layer (`.adx/` manifests + recovery + module map), a deep `docs/` tree (architecture, threat-model, honey-keys, scanners, setup, troubleshooting, glossary/vocabulary, ADRs with a `REJECTED/` folder), and CHANGELOG/CONTRIBUTING/SECURITY. The README is unusually candid for an early-stage tool: a "What's real vs. what's not yet" table marks External Surface and IaC-Pack run-mode as honest "Coming Soon," and I verified that every CLI command and flag the README documents maps to a real dispatch branch or `add_argument` in `cli.py` (flat `security-scan` argparse with positional `target` dispatch; default port 8765 matches; `ioc`/`dashboard`/`doctor`/`template`/`schedule` and the `--quick/--full/--secrets/--deps/--trust/--trust-cache-only/--platform-posture/--fail-on/--json/--all-repos` flags all exist). The MCP documentation is a standout: `mcp/README.md` accurately describes **both** the read-only default (`devsec-mcp`) and the guarded write mode (`devsec-mcp-rw`) — with a full "Guarded write mode" section covering the `case_followup_prompt → preview_case_resolutions → apply_case_resolutions` flow, `devsec.case_resolutions.v1` validation, and read-only-by-default guarantees — and both entry points are real in `pyproject.toml`. That is the trust/permission honesty the Brief demands. Against that strong baseline, this lens found **one isolated, concrete drift and one stale caveat**. The drift: **AGENTS.md line 41 understates the adapter as "read-only access ... stdio-only" only**, contradicting both README:43 and the entire `mcp/README.md` it points to — the canonical agent guide is the single place denying the audited write path that the rest of the docs and the shipped binary confirm exists. The stale caveat: AGENTS.md tells agents to "run `uv run pytest`," while `.adx/verification.json` notes that same pytest path is "currently blocked until pytest exists in the selected Python environment" — yet `pyproject.toml` declares `pytest>=9.0.3` in `[dependency-groups]` and the repo has 46 test files, so the JSON caveat reads as out-of-date rather than a real gap. Net: **the documentation is comprehensive, trust-aware, and largely truthful-to-code; the two priority repairs are narrow — (1) fix the one-line AGENTS.md MCP understatement to match README/mcp-README, and (2) refresh the stale `.adx/verification.json` pytest caveat (or confirm the blocker) so the verification story is internally consistent.**
